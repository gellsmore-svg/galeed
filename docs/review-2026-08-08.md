# Galeed — functional and code review

**Date:** 2026-08-08 · **Reviewed:** `master` @ `35a226f`, `pyproject` at
**0.3.2** (four files uncommitted: `decisions.py`, its test, CHANGELOG, version)
**Method:** the CLI and HTTP API were exercised against the **live
`mnemosyne_dev` spine** (235 `llm_calls`, 2,300+ trace events, read-only), the
cost helpers and hook bridge were probed directly, then the source was read.
Every claim below is backed by a run or a query, reproduced inline.

> **Disclosure.** The token-usage/cost work in `src/galeed/llm_calls.py`
> (commit `77a5bc4`) was written by this reviewer. Two findings — H1 and M3 —
> are against that code, and H3 is against a claim this reviewer made elsewhere.

## Part 1 — Functional review

**Baseline:** `46 passed` in 0.71 s. `ruff check src tests` clean, rule set
pinned with the explanatory comment, CI gates both. Stdlib-only core, as
advertised.

### What works

**`galeed trace` delivers exactly what the README promises.** Run against the
live spine it renders the full In→Out call tree with the complete prompt
captured — not a truncated preview:

```
╭──────────────────────────────────────────────────────────────────────────────╮
│ 064471db-…  exp1-074844-4 · 1 call(s)                                        │
│ └── ● mistral-small:latest                                                   │
│     In:                                                                      │
│     Analyse the REASONING below for logical fallacies. Judge ONLY the form   │
│     of the inference …                                                       │
```

This is the debugging layer working as designed, and it is the reason the other
reviews in this estate could inspect what models were actually sent.

Also verified:

- `galeed sessions` summarises across sources (`codex`, `hoglah`, `tirzah`,
  `feedback`) with event and trace counts.
- The HTTP API answers `200` on `/api/trace/sessions`, `/api/llm-calls`, and
  `/api/trace/events`; binds `127.0.0.1`; read-only; the docstring says plainly
  there is no auth.
- `correlation_ids` handles every case correctly — flat fields, nested
  `metadata`, top-level winning over metadata on conflict, and non-string
  coercion.
- `TraceBus` uses bounded queues (`max_queue=1000`) with non-blocking
  `put_nowait` and drops on a slow consumer rather than blocking a request. That
  is the right trade for telemetry.
- `web.py` closes its `MongoClient` on shutdown **only when it opened it**
  (`owned_client`) — a careful version of a fix that is usually done bluntly.

### Functional defects

#### F1. The cost estimator cannot produce a non-zero number

`estimate_cost_usd` is the family's only cost function. Its rate table ships
with a single entry:

```python
DEFAULT_COST_PER_1M = {'default': {'in': 0.0, 'out': 0.0}}
```

There are no model rates at all, so every model resolves to the zero default:

```
cost(1M in + 1M out, model=None                 ) = 0.0
cost(1M in + 1M out, model=gemma4:e2b           ) = 0.0
cost(1M in + 1M out, model=claude-opus-5        ) = 0.0
cost(1M in + 1M out, model=gpt-5                ) = 0.0
```

Two million tokens on a frontier model costs `$0.00`, and that value is
indistinguishable from genuinely free local inference. The docstring is careful
about the *other* unknown — *"Returns `None` when usage has no token counts
(unknown, not free)"* — but an **unpriced model** silently becomes free rather
than unknown.

#### F2. Half the spine carries no cost or latency signal

Measured across all 235 live `llm_calls`:

```
usage.total > 0 :  91 (39%)      duration_ms set :  98 (42%)

  hoglah   n=116  usage>0= 91  duration= 98
  tirzah   n=119  usage>0=  0  duration=  0
```

The Hoglah instrumentation works. **Tirzah writes 119 calls with neither token
counts nor duration** — every direct answer-adapter call is uninstrumented.

This matters beyond Galeed. An earlier assessment in this estate asserted that
"104 LLM calls are recorded and zero carry duration or tokens" and treated
instrumenting them as the precondition for evaluating the architecture. That fix
was applied to Hoglah only. On today's data the estate still cannot answer what a
run costs, because the larger producer reports nothing and the estimator (F1)
could only return zero anyway.

Galeed is the spine and has no coverage reporting of its own — `galeed sessions`
shows event counts, never instrumentation coverage.

#### F3. The agent hooks add ~2 s per invocation when Mongo is unreachable

`_get_db()` opens a client with `serverSelectionTimeoutMS=2000` and issues
`client.admin.command("ping")` on **every** hook invocation. Measured against an
unroutable host:

```
_get_db() with Mongo unreachable: 2.12s, 2.01s
PreToolUse + PostToolUse per tool call => ~4.2s added per tool call
over 100 tool calls => ~7.1 minutes of added latency
```

The docstring says *"hooks must be best-effort and never block the agent."* It
never *fails* the agent, but two seconds per hook — twice per tool call, on every
tool call — is blocking in any practical sense. Each hook is a fresh process, so
nothing learns that Mongo is down and every invocation pays it again.

## Part 2 — Code review

### High

#### H1 · `llm_calls.py:91-113` — `estimate_cost_usd` conflates "unpriced" with "free"

```python
table = rates or DEFAULT_COST_PER_1M
rate = table.get(model or "", table.get("default", {"in": 0.0, "out": 0.0}))
```

Code side of F1. The function is structurally correct — it takes an injectable
`rates` table, normalises the token aliases, and returns `None` when usage
carries no counts. What is missing is that the shipped table has no rows, so the
`default` branch is the only branch ever taken.

**Fix:** return `None` when the model is not in the table and the caller supplied
no rates, reserving `0.0` for models explicitly priced at zero (local Ollama).
Optionally ship rates for the models the family actually calls. The one-line
version is:

```python
rate = table.get(model or "")
if rate is None:
    return None if model else table.get("default")
```

*(Reviewer's own code.)*

#### H2 · `hooks.py:38-51` — a 2 s connection probe on every hook invocation

```python
client = MongoClient(uri, serverSelectionTimeoutMS=2000)
client.admin.command("ping")   # quick check
```

Code side of F3. The `ping` is what makes the failure slow: without it, pymongo's
lazy connection would fail on the first write and could be given a much shorter
budget.

**Fix, cheapest first:** drop `serverSelectionTimeoutMS` to ~250 ms for the hook
path (a local Mongo answers in single-digit ms); and write a short-lived
breadcrumb (e.g. `~/.galeed/mongo-unreachable`, valid 60 s) so subsequent hook
processes skip the probe entirely rather than each re-paying it.

#### H3 · No instrumentation-coverage surface

Code side of F2. `record_llm_call` accepts a call with no `usage`, no
`duration_ms` and no `started_at` without comment — correctly, since telemetry
must never fail a request. But nothing anywhere reports how much of the spine is
instrumented, so a producer that silently stops reporting usage (as Tirzah never
started) is invisible.

Hanani solves exactly this problem with a first-class `gaps` command that states
its own coverage in plain language. The same idea belongs here: `galeed sessions`
should show, per source, what fraction of calls carry usage and duration. It is a
single aggregation over a collection Galeed already owns, and it is the cheapest
way to stop cost claims across the estate from drifting from the data.

### Medium

#### M1 · `events.py:24` — `SCHEMA_VERSION` is written and never read

```
src/galeed/events.py:24   SCHEMA_VERSION = "1.0"
src/galeed/events.py:154  schema_version: str = SCHEMA_VERSION
```

Those, plus the re-export in `__init__.py`, are the only occurrences. No reader —
not the CLI, not the web API, not the recorder — compares an event's
`schema_version` against the one it understands.

The README's schema discipline (*"bump it only on a backwards-incompatible
change"*) is therefore one-directional: producers stamp, consumers ignore. If the
version were bumped tomorrow, nothing would notice, which removes the only
benefit of carrying the field. Keturah, by contrast, validates
`MANIFEST_SCHEMA_VERSION` on read.

**Fix:** have the read paths warn (not fail) on an unrecognised major version.

#### M2 · `bus.py:36-40` — dropped events are silent

```python
try:
    sub.put_nowait(event)
except queue.Full:
    pass  # slow consumer: drop rather than block the request
```

Dropping is the right behaviour; doing it invisibly is not, in a component named
"heap of witness". A slow SSE viewer loses events and neither the publisher nor
the subscriber learns that the stream has holes.

**Fix:** a per-bus dropped counter, exposed on the bus and in `galeed sessions`.

#### M3 · `llm_calls.py:74-82` — alias normalisation stores each count twice

`_merge_usage` writes both spellings (`tokens_in` **and** `prompt_tokens`,
`tokens_out` **and** `completion_tokens`), so a stored `usage` holds five keys
for three numbers. Good for query compatibility, but any consumer that sums the
numeric values of `usage` — a natural thing to do with a token dict — double
counts. Live example:

```json
{"prompt_tokens": 4, "completion_tokens": 25, "total": 29}
```

(older record, pre-alias) versus a current one carrying all five. Consumers now
have to know which keys are canonical.

**Fix:** store the canonical pair plus `total`, and normalise aliases on read
instead. Failing that, document the canonical set in the README.
*(Reviewer's own code.)*

#### M4 · `cli.py:50` and `hooks.py:47` — `MongoClient` is never closed

Both are short-lived processes so nothing leaks in practice, and `web.py` — the
long-lived one — does close correctly. Recorded for completeness, and because the
hook path pays full connection setup per event (H2).

### Low

#### L1 · Uncommitted work in the tree

`decisions.py`, `tests/test_decisions.py`, `CHANGELOG.md` and the version bump to
0.3.2 are modified but not committed. The last release commit is 0.3.1. A fresh

## Comparison with the other six reviews

Galeed is the spine the other six emit into, which makes one finding here
disproportionately important: **F1 + F2 mean the estate's cost story is still not
answerable.**

That is worth stating plainly because this reviewer previously asserted the
opposite direction. The roles assessment identified "no cost instrument exists in
this stack" as the blocking gap and instrumenting it as action #1. The
instrumentation landed for Hoglah (78% usage coverage, verified above) and the
conclusion was treated as settled. On today's data:

- Tirzah — the larger producer, 119 of 235 calls — reports nothing at all;
- the cost estimator can only ever return `0.0` or `None`.

So the measurement that was supposed to make the architecture evaluable is half
wired and terminates in a constant. This is the estate's **degenerate-constant**
family (Hoglah's Prometheus counters, Milcah's `global_coherence`, Hanani's
all-`True` audit scores) appearing in the reviewer's own contribution, which is a
useful check on the pattern being real rather than a stylistic complaint.

The other estate-wide property holds here too, in its mildest and most
appropriate form: **silence**. A dropped bus event, an unstamped schema version,
an uninstrumented producer, a 2-second hook stall — all correct decisions for
telemetry taken individually (never fail the request), and all invisible
collectively. Galeed is the one product where "never fail, never mention" is
defensible by design; it is also the one where a coverage surface would pay for
itself across six consumers.

## Suggested order

1. **H1** — make unpriced models return `None`, not `0.0`. Five lines, and it
   stops a fabricated number entering every cost aggregate.
2. **H3** — per-source usage/duration coverage in `galeed sessions`. One
   aggregation; it is what would have caught F2 without a manual query, and the
   Hanani `gaps` command is the model to copy.
3. **F2 (Tirzah side)** — thread usage and duration through Tirzah's direct
   answer path, as Hoglah already does. Belongs in Tirzah's backlog, referenced
   here because Galeed is where the gap is visible.
4. **H2** — shorter hook timeout plus an unreachable breadcrumb.
5. **M1, M2** — schema-version warning on read, dropped-event counter.
6. **M3, M4, L1** — small.

Nothing here is architectural. The event vocabulary, the tracer, the bounded bus,
the ownership-aware client close and the In→Out debug view are all right, and the
trace viewer is the most useful single tool in the estate. The findings are one
empty lookup table, one missing aggregation, and one timeout.
